# Changelog

All notable changes to nuclear-vscode are written here; versions follow [Semantic Versioning](https://semver.org).

## Unreleased

- First public version.
- 0.45.0: every call to the local agents carries the project's folder (`root`), so an agent reads by itself the files that declare the names of its task (the Loop and the chat); the Plan step says how many things of the spec are beyond the platform or the local agents (the planner's `limits`) and shows the plan as a tree; *Tests first* is skipped when the generators wrote every file of the run (ADR-0104).
- 0.44.0: the Loop's *Generate* stage (before Plan) runs `dragonfly gen` for the spec's resources; its files are undone like the agents' (ADR-0103).
- 0.46.0: the Loop follows the strategy of the request (ADR-0105): the *Specification* stage ends with the analysis (`/developer/analyze`), which decides the stages that run, adds the generator calls it read in plain words to *Generate*, gives *Plan* the pieces the tools found (a rename's files are written as the tool gave them), stops the run with the questions when the request lacks a fact, and after *Code* wires each use case with `dragonfly gen usecase`; for a bug, *Verification* repairs the file the failure names and never the test; a spec may name its strategy (`- Strategy:`).
- 0.47.0: right-click menu in the Nuclear workspace file tree: New File/Folder, Rename and Delete (to the trash), and *New with Dragonfly* (`dragonfly make`/`gen`) limited to what the clicked folder and the platform allow; build/, node_modules/ and the files that make a project are protected.
- 0.48.0: the set-up of the AI services (ADR-0106). *Nuclear: Set Up the AI Services* is a wizard in four steps: this machine (processor, memory, GPU, disk) and where the agents run (here, or remote agents only); the profile (`lite`, `medium`, `hard`: what each downloads, the memory it wants, what works and what does not, one suggested for the machine); what it needs (NuclearLang, uv, Ollama: found by itself once installed, or installed in a terminal); the installation with its progress and *Try again*. Offered once on a machine never set up; *Set-up…* in *Settings and integrations*, whose Start and Restart now go through the system's services. `nuclear-loop setup [--profile <id>] [--yes] | --status | --remove` is the same set-up in a terminal. The services start at every login (systemd user units, launch agents, the Startup folder). The Loop's and the editor's default models are the ones of the machine's profile (`~/.config/nuclearlang/ai.env`).
